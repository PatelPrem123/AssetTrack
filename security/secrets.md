## 2. Environment & Configuration Handling

### Current Implementation Standards
1. **Strict Separation of Secrets:** Secrets are loaded strictly into `process.env` on server initialization via `dotenv.config()`.
2. **Template Provisioning:** A sanitized template `.env.example` must be maintained in `server/`, containing placeholder values only:
   ```env
   NODE_ENV=development
   PORT=5000
   MONGODB_URI=mongodb://localhost:27017/assettrack
   JWT_SECRET=replace_with_64_character_hex_string
   JWT_EXPIRES_IN=7d
   COOKIE_SECRET=replace_with_secure_random_string
   BASE_URL=http://localhost:5173
   ```
3. **No Defaults for Production:** The application bootloader (`server/src/config/db.js` & `server/src/index.js`) must validate that `JWT_SECRET` is not set to default strings ("secret", "123456", "admin") when `NODE_ENV === 'production'`.

## 3. Threat Surfaces & Risk Assessments

### A. Hardcoded Secret Risks
- **Risk Assessment:** **LOW (No hardcoded secrets detected).**
- **Evidence:** Audit of `AssetTrack_Comprehensive_Documentation.md` and repository files shows zero hardcoded database passwords, plaintext JWT secrets, or cloud credentials.
- **Enforcement Rule:** Pre-commit hooks (`git-secrets` or `gitleaks`) must be configured to block any commit containing AWS keys, MongoDB connection strings with plaintext credentials, or private keys.

### B. Client-Side Exposure Risks
- **Risk Assessment:** **LOW.**
- **Evidence:** The client is a React 18 SPA built with Vite. Vite strictly isolates environment variables: only variables prefixed with `VITE_` are bundled into the public client JavaScript payload.
- **Rule:** `VITE_API_URL` is the only permissible client-side environment variable. Under no circumstance shall database credentials, JWT secrets, or administrative master keys be prefixed with `VITE_`.
- **Physical QR Barcode Surface:** QR codes generated by the system contain only opaque URL paths (`/q/AT-ORG01-0042`) and never leak internal IP addresses, Wi-Fi passwords, or employee credentials (`DEC-004`).

### C. Git & History Exposure Risks
- **Risk Assessment:** **LOW (Strict Git hygiene configured).**
- **Evidence:** `.gitignore` must strictly include:
  ```gitignore
  .env
  .env.local
  .env.production
  node_modules/
  dist/
  uploads/
  coverage/
  *.log
  ```

### D. Logging & Error Exposure Risks
- **Risk Assessment:** **LOW (Sanitized error handler).**
- **Evidence:** Centralized Express error-handling middleware strips internal stack traces, database connection URIs, and system paths before returning JSON error responses when `NODE_ENV === 'production'`:
  ```javascript
  res.status(statusCode).json({
    success: false,
    message: err.message || 'Internal Server Error',
    ...(process.env.NODE_ENV === 'development' && { stack: err.stack })
  });
  ```

## 4. Secret Rotation Requirements

| Secret | Rotation Frequency | Rotation Procedure & Impact |
| :--- | :--- | :--- |
| `JWT_SECRET` | Every 90 days or immediately upon compromise. | Update `.env` and restart service. Active user sessions are invalidated; users must re-authenticate. |
| `MONGODB_URI` | Every 180 days. | Update database user password in MongoDB Atlas / cluster, update `.env`, perform zero-downtime rolling restart. |
| `COOKIE_SECRET` | Every 90 days. | Signed cookies are regenerated on subsequent user requests. |
